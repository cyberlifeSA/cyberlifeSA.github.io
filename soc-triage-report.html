1. Resumen Ejecutivo

  • True Positives (TP): 39 (97.5%)
  • False Positives (FP): 1 (2.5%)
  • Severidad Critica: 8 alertas (20%)
  • Severidad Alta: 10 alertas (25%)
  • Severidad Media: 18 alertas (45%)
  • Severidad Baja: 4 alertas (10%)

5. Casos Destacados

5.1 Caso Critico: Windows OLE Zero-Click RCE (SOC336)

  • Severidad: Critical
  • TTPs: T1566.001, T1203, T1218.010, T1059.003
  • Resumen: Exploit zero-click en Windows OLE que permite ejecucion remota de codigo sin interaccion del usuario.
  • Accion: Triage completo, enriquecimiento de IOC, escalamiento a incidente critico.

5.2 Caso Critico: Lumma Stealer via Phishing (SOC338)

  • Severidad: Critical
  • TTPs: T1566, T1218, T1059
  • Resumen: Stealer distribuido mediante campana de phishing con tecnica Click Fix.
  • Accion: Identificacion de DLL side-loading, bloqueo de IOC, documentacion de cadena de ataque.

5.3 Caso de Falso Positivo: Phishing Interno (SOC120)

  • Severidad: Medium
  • Resultado: FP
  • Resumen: Alerta de phishing interno a interno que resulto ser comunicacion legitima.
  • Accion: Cierre como falso positivo con justificacion documentada. Demostracion de capacidad de descarte.

5.4 Caso APT: Zebrocy Malware (SOC331)

  • Severidad: Medium
  • TTPs: T1566.001, T1204.002, T1057, T1082
  • Resumen: Actividad de malware Zebrocy asociado a APT28.
  • Accion: Enriquecimiento de IOC, mapeo a MITRE, documentacion de cadena de ataque.

6. Proceso de Triage Aplicado

  1. Recepcion de alerta - revision de campos (source, destination, user, host, process, command line, hash)
  2. Clasificacion inicial - revision de severidad reportada por el SIEM (Critical, High, Medium, Low)
  3. Enriquecimiento de IOC - consulta a VirusTotal
  4. Mapeo MITRE ATT&CK - identificacion de TTPs
  5. Analisis de contexto - revision de logs adicionales, correlacion con otras alertas
  6. Veredicto - True Positive (TP) o False Positive (FP)
  7. Documentacion - registro en bitacora con evidencias, cronologia y acciones

8. Fortalezas Demostradas

  • Analisis de alertas complejas: RCE, phishing, malware, APT, brute force
  • Enriquecimiento de IOC: uso de fuentes CTI (VirusTotal)
  • Mapeo MITRE ATT&CK: identificacion y documentacion de TTPs
  • Clasificacion de severidad: segun severidad reportada por el SIEM (Critical, High, Medium, Low)
  • Descarte de falsos positivos: caso SOC120 documentado con justificacion
  • Documentacion estructurada: bitacora con evidencias, cronologia y veredicto

9. Brechas Identificadas (para mejora)

  • MTTA/MTTR: no se registraron tiempos formales de reconocimiento y respuesta por alerta
  • SLA: no se documento cumplimiento de acuerdos de nivel de servicio
  • Escalamiento formal: no se simularon handovers ni escalamientos a MDR/IRM
  • Ticketing: no se uso sistema de ticketing real (Jira, TheHive, etc.)
  • Notificaciones al cliente: no se documentaron comunicaciones formales

10. Recomendaciones para Proximos Pasos

  1. Registrar MTTA y MTTR por cada alerta para generar metricas operacionales reales
  2. Simular escalamientos a MDR/IRM con documentacion de que informacion se entrega
  3. Practicar handovers con casos abiertos entre turnos simulados
  4. Usar un sistema de ticketing (TheHive, Jira, o incluso GitHub Issues) para documentar casos
  5. Generar reportes semanales con metricas: alertas recibidas, casos cerrados, SLA compliance
